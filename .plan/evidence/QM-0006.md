## Summary

Commit `103297d` ("Refactor workspace references from matrix-workspace to
quatricmorph-workspace") rewrote every *reference* from
`apps/web/matrix-workspace` to `apps/web/quatricmorph-workspace` across 57 files
— including `apps/web/vitest.config.ts`, `apps/web/package.json`,
`.github/workflows/build.yaml`, `STATUS.md`, `README.md` and four accepted ADRs —
but never renamed the directory.

Nothing failed loudly. The two `include` globs in `apps/web/vitest.config.ts`
that address the workspace matched zero files, so `npx vitest run` reported
`Test Files 3 passed (3) / Tests 27 passed (27)` at **exit 0** while silently
collecting none of the nine test files under the workspace, which hold 74 tests.
`npm run build --workspace quatricmorph-workspace` exited 1 with
`npm error No workspaces found`.

This task completes the rename with `git mv` (112 renames, history preserved),
fixes the double-sed package name `quatricmorph-quatricmorph-workspace` →
`quatricmorph-workspace`, regenerates `apps/web/package-lock.json`, and adds a
regression guard that fails whenever a declared workspace path or a vitest
`include` glob does not resolve on disk.

Direction was forced, not chosen: reverting the configuration to
`matrix-workspace` would require editing four accepted ADRs and `STATUS.md`
outside the tasks that own them. Renaming the directory edits neither.

**All 74 recovered tests pass. No regression was hidden behind the broken
collector.**

1. **AC-2's literal `12 files / 101 tests` and the post-fix full-suite number

2. **The guard's glob matcher is `node:fs.globSync`, not vitest's matcher.**

   23.7.0 and prints an `ExperimentalWarning` on stderr during every web test
   run; it is noise, not failure.

   module.** A config that computed its globs at runtime would defeat the
   extractor. `the_vitest_config_still_declares_the_include_globs_this_test_reads`

   validate a config shape it cannot parse. That same test asserts

   literal — a deliberate trade to keep the anti-vacuous-pass property.

   deliberately hardcodes no test count, so future floor-raising tasks do not
