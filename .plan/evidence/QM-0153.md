## What was already there, and what this task added

`QM-0150` shipped `MAX_HEATMAP_CELLS = 250_000`, column merging by maximum, and
the dashed-border aggregation mark. It did **not** have:

* a `CellFidelity` type at all — a cell carried a boolean `aggregated` and the
  manifest's `fidelity` word, with nothing that classified the two together;
* any mark for the engine's own coarseness. A `sampled` run drew exactly the
  same picture as an `exact` one, distinguished only by header and row-label
  text and a `data-fidelity` attribute;
* a separate legend entry for that state, or any line saying which coarseness
  is whose;
* a coverage assertion at the extreme dimensions the task names.

So the task's centre of gravity here is the labelling and the anti-truncation
proof, not the ceiling arithmetic.

## How the marks survive greyscale

Neither mark is a colour, and neither changes between palettes:

* **Aggregation** is a dashed *outline* (`stroke-dasharray="3 2"`), unchanged
  from `QM-0150`.
* **Engine coarseness** is a filled triangular *wedge* in the cell's top-right
  corner. `the_sampled_wedge_survives_greyscale_because_it_is_a_shape_and_not_a_colour`
  asserts the emitted `<path>` elements are byte-identical under
  `palette: 'colour'` and `palette: 'greyscale'`, and that their ink is one of
  two values (`#111827` over the light end of the ramp, `#ffffff` over the dark
  end — the same flip the magnitude glyph uses, so the mark cannot vanish into a
  dark fill).

A solid shape against a broken outline is a distinction of *kind*, not of
lightness, so it also survives a reader who cannot separate the hues.
`aggregated-greyscale.svg` is committed as the degraded state in greyscale and
`aggregated-colour.svg` as the same state in colour; their cell fills are
`#3d3d3d / #737373 / #fcfcfc` and `#800026 / #e31a1c / #ffffcc` respectively,
and both carry `stroke-dasharray="3 2"` on all three cells. Those two are an
`exact` run, so they carry the dash and no wedge. The pair that carries **both**
marks is `sampled-greyscale.svg` in greyscale (2 cells, both dashed, 2 cell
wedges plus the legend one) and `sampled-experts-colour.svg` in colour (2 cells,
both dashed, 3 wedges, wedge ink `#111827` on the light fill and `#ffffff` on
the darkest — the ink flip doing its job). No `sampled-colour.svg` exists; the
colour half of that claim rests on the experts artifact.

## The three states, and two deliberate decisions

```ts
export type CellFidelity =
  | { kind: 'exact' }
  | { kind: 'aggregated'; channelsPerCell: number | null }
  | { kind: 'sampled' }
```

1. **`channelsPerCell` is `number | null`, not `number`.** The task's data
   contract writes `number`. `Cell.channelsPerCell` has been `number | null`
   since `QM-0150` because manifest v1's summary projection publishes one number
   per layer and no shape — the channel extent is genuinely unpublished there.
   Narrowing to `number` would have forced a claim of one channel, which is a
   resolution the manifest never gave. This is the minimal widening that keeps
   the type from inventing an extent, and it is asserted by
   `an_aggregated_cell_with_no_published_extent_says_so_rather_than_claiming_one_channel`.

2. **Precedence is engine-over-renderer, and nothing is lost by it.** A merged
   cell of sampled numbers classifies as `sampled`: a reader told only "merged"
   would believe the underlying numbers were complete. `Cell.aggregated` and
   `Cell.channelsPerCell` remain on the cell, both marks are drawn when both
   apply, and both legend entries appear.

An `approximate` run shares the wedge with a sampled one — the contract has
three variants and a fourth would break it — but **no string a reader sees says
"sampled" about an approximate value**. Every displayed word comes from the
manifest's own `fidelity` field, and
`an_approximate_engine_value_is_never_described_to_the_reader_with_the_word_sampled`
asserts that over `surfaceStrings()` and over every `<text>` node of the
rendered image. The `data-cell-fidelity="sampled"` attribute an approximate run
emits is a machine attribute for marker selection, never drawn as text; it is
called out here rather than left to be discovered.

For the same reason the *legend entry kind* is `'engine-coarse'` and not
`'sampled'`: a field of the surface value literally holding `sampled` on an
approximate run is precisely the mislabelling `surface.test.ts`'s
`fidelityBearingPaths` walker exists to catch.

## Acceptance criteria

| # | Criterion | Where it is proved |
| --- | --- | --- |
| 1 | Cell count never exceeds the ceiling at any dimension | `the_cell_count_stays_inside_the_ceiling_at_dimensions_that_divide_badly` (5 shapes that divide badly), plus the two extreme-size tests |
| 2 | Aggregated cells carry a persistent marker, legible without hover and in greyscale | `the_sampled_wedge_is_a_different_mark_from_the_aggregation_dash`; `QM-0150`'s `an_aggregated_cell_is_drawn_with_a_dashed_border_a_reader_can_see_without_hovering` |
| 3 | The legend states the factor and that merging is by maximum | `the_aggregation_factor_is_stated_in_the_legend_and_drawn_in_the_image`, `the_legend_says_the_merge_is_by_maximum_and_says_why_it_is_not_a_mean` |
| 4 | `sampled` is visually distinct from `aggregated` | `a_sampled_cell_carries_a_corner_wedge_and_an_exact_one_does_not`, `the_sampled_and_aggregated_legend_entries_are_two_entries_and_not_one` |
| 5 | **No truncation path exists** | `every_channel_index_maps_into_exactly_one_cell_at_a_thousand_layers_of_sixty_five_thousand_channels`, `every_row_of_a_grid_built_at_the_ceiling_covers_every_one_of_its_channels`, `no_band_is_dropped_even_when_the_manifest_publishes_no_channel_extent` |
| 6 | Factor 1 renders identically to the unaggregated case | `a_row_that_needed_no_merging_is_identical_to_the_same_row_planned_with_room_to_spare`, `unit_wide_bands_at_factor_one_carry_no_aggregation_mark_and_no_aggregated_legend_entry` |

On criterion 5, the coverage check is run three ways so that no single blind
spot hides a dropped channel: a per-channel occupancy count (every index covered
exactly once — zeroes mean a truncated tail, twos mean an overlap), the total
band count (`sum(bandsPerCell) === bands.length`, which still holds where the
manifest publishes no extent and the occupancy check is blind), and the last
cell's `channelEnd` reaching the channel count at every shape tested.

On criterion 6, the literal wording ("aggregation factor of 1 → no marker")
conflicts with `QM-0150`'s deliberate and tested behaviour: a cell covering more
than one channel is an aggregate whatever the merge factor, because manifest v1
publishes one number per whole tensor. That test was **not** relaxed. The
criterion is proved in the case it can be true in — the renderer merged nothing
*and* each band is a single channel — and as a structural identity between a
row planned with exactly enough columns and the same row planned with room to
spare.
