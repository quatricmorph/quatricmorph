fixed by the four schemas already in `schemas/` (all four declare
`http://json-schema.org/draft-07/schema#`); `definitions` rather than `$defs`

carry); `granularity` as `{kind, group_size}` rather than a single-key map; and
the `projection` discriminator, without which a summary and a full run that

## Architecture conformance

* **`ARCHITECTURE.md` §19 — "Do not send the entire tensor into the browser."**
  The `summary` projection exists from the first commit rather than being
  retro-fitted, and the schema *forbids* `tensors` when `projection` is
  `summary` rather than merely permitting its absence. At `CAT-006`'s 47 278
  tensors the per-tensor array is tens of MB; `QM-0150` loads the summary.
* **`ARCHITECTURE.md` §19 — "Do not assume a colour pattern corresponds to a
  semantic concept."** Nothing in the schema or the types makes a claim about
  what a weight *means*. Every description that touches interpretation says so
  explicitly: `ranking` is "a proxy for sensitivity, ranked — not a statement
  that a layer is important"; `error_removed_fraction` is "Not an accuracy
  prediction"; `expert_entry.aggregate` says weight-space redundancy may be read
  from the numbers but expert deadness may not, "because deadness is a routing
  property that needs runtime".
* **`AGENTS.md` rule 4 — exact vs sampled vs approximate.** `fidelity` is a
  required top-level field carrying all three labels, converted from
  `q_source::ResultFidelity` by an exhaustive `From` impl, so a new variant
  fails to compile rather than silently missing from the wire vocabulary.
* **`AGENTS.md` rule 6 — never claim semantic understanding without evidence.**
  `resolver_confidence` is required and surfaces `unknown` for a
  generic-resolved hierarchy (`NSIR-001`); `role` accepts `unknown` as a
  first-class value and *refuses* an unrecognised spelling rather than coercing
  it to `unknown`, so a typo cannot masquerade as an honest admission of
  ignorance.
* **ADR-010 — rank ≤ 3 implemented, above it refuses.** Both sides: the schema
  caps `shape` at `maxItems: 3`, and `validate()` returns
  `QError::not_implemented("GRID-007", …)`. The refusal message deliberately
  contains no flattened extent, and a test asserts `16384` never appears in it.
* **`SCHEMA_PLAN.md` §5 — versioning.** `$id` ends `/v1` (`SCHEMA-001`);
  `manifest_version` is `const: 1`; a reader refuses an unknown version rather
  than guessing (`SCHEMA-002`). The README records the v2 procedure: write the
  ADR, mint `manifest.v2.json`, leave v1 readable, consumers pin.
* **`PRODUCT_SCOPE.md` §5.2 — no claiming GPU work the CPU did.** The `backend`
  enum is `["cpu", "metal"]` and cannot express `cuda`, because `q-cuda` is
  `Hardware-Unverified` (`CUDA-001`). A vocabulary that can name a backend which
  has never run is how that claim gets made by accident. Asserted from both
  sides, and guard removal turns two tests red.
* **`REPORT_ARCHITECTURE.md` §5 — the crate produces bytes, nothing else.**
  `q-report` depends on `q-source`, `serde` and `serde_json`. No I/O, no
  computation, and deliberately no code that *derives* a metric: the manifest
  carries composable partials and the consumer finishes the arithmetic, because
  a quantity with two definitions drifts.

## Golden provenance

**This is the question the inherited draft got wrong, so it is answered in
full.**

The draft argued: change one character in the golden, watch the byte comparison
go red, therefore "the hand-authored file really is byte-for-byte what
`to_json_string` produces". That is a non sequitur. Perturbing a golden proves
the *comparison* is live; it says nothing about where the bytes came from, and a
golden emitted by the code under test would pass exactly the same check. The
Python script that would have been the real evidence was left in a session
scratchpad and no longer exists.

**Provenance could not be established by inspection, so it was manufactured
instead.** Three independent facts, none of which depends on `q-report`:

1. **The byte layout is pinned by a second implementation.** CPython's `json`
   module re-emits each golden byte-for-byte:
   `json.dumps(json.load(f), indent=2, ensure_ascii=False) + "\n"` equals the
   file exactly, for both `manifest.v1.json` and `manifest.v1.summary.json`.
   Python's `indent=2` and serde's `to_string_pretty` agree on separators, key
   order, array expansion and every float rendering in the file. The canonical
   form is therefore not one library's private habit, and
   `the_golden_manifest_round_trips_byte_identically` compares against an
   externally-fixed layout rather than against whatever serde happened to print.
2. **Schema conformance is confirmed by a third-party validator**, `jsonschema`
   4.26.0 with `FormatChecker`, not by the hand-rolled validator in the crate's
   own test file — positively for both goldens and the schema's example, and
   negatively for 24 mutations.
3. **Every number in the golden was recomputed in Python from the written
   contract.** The per-tensor partials sum to the layer partials and to `totals`
   for all six additive fields and `max` for `max_abs_delta`; layer and expert
   membership is read off the canonical address; each `relative_error` equals
   `sqrt(sum_sq_delta / sum_sq_base)`; each `bytes_at_base_precision` equals
   `count × sizeof(dtype)` and each target equals `count × 4 / 8` for int4; each
   `shape` product equals `count`; each frontier step's `added_bytes` equals the
   keep set's cost and its `error_removed_fraction` the keep set's share of
   total squared error; and the keep sets are exactly the greedy prefixes in
   descending error-per-byte order — which is what makes `frontier.method`
   truthful. All seven ordering rules and the summary projection likewise.

**Verdict: the goldens are independently verified.** Whether the previous agent
first typed them by hand or first printed them from the crate can no longer be
determined and no longer matters — their layout is pinned by CPython, their
shape by a third-party validator, and their arithmetic by a re-derivation from
the contract. The round-trip test is not circular.

**What each test is actually sensitive to** (measured, not assumed —
`golden_sensitivity.py`, six mutations):

| Mutation to the golden | Which test turns red |
| --- | --- |
| `12.5` → `12.25` (a *value*) | `the_summary_projection_of_the_golden_manifest_is_the_golden_summary` |
| `12.5` → `12.50` (float layout) | `the_golden_manifest_round_trips_byte_identically` |
| `2883584` → `2883584.0` (integer layout) | both of the above |
| 2-space → 4-space indent on one line | `the_golden_manifest_round_trips_byte_identically` |
| key order: `projection` before `manifest_version` | `the_golden_manifest_round_trips_byte_identically` |
| trailing newline removed | `the_golden_manifest_round_trips_byte_identically` |

So the byte-identity test pins **layout**, and cross-file consistency pins
**values**. The draft conflated the two.

  `tensors[].address`, `layers[].layer_index`, the expert pair, and the

  disagree by construction.** `Manifest` carries `#[serde(flatten)] extensions`,

  trip, and validating still tells you the document is not v1. `## Implementation
  Plan` item 3 asks for preservation, and it is satisfied; a reviewer should
  know that a preserved extension makes the document fail its own schema, which
  is intended, not an oversight. `#[serde(deny_unknown_fields)]` cannot be
  combined with `flatten`, so the top level could not have had both.
