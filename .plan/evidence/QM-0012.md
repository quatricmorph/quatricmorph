# QM-0012 — Config-derived model metadata

## Task

`QM-0012` — Model-level metadata from `config.json`: parse it in `q-architecture`,
persist it in `q-catalog`, wire it through `q-safetensors` ingestion, surface it
on `GET /v1/models/{id}` and `q inspect`.

Lane T · Wave 2 · Phase 01 (SafeTensors ingestion completion).
Requirements introduced: `NSIR-010`, `CAT-011`. Enables `MVP-06`.

Dependency note: `TASK.md` `## Dependencies` names `QM-0005`, which is
`Deferred` for v1. `.plan/EXECUTION_ORDER.md` §10 rewires this task's v1 edge to
**none — Ready** ("Feeds the manifest's `model` block"). Confirmed by reading
that table; `QM-0005` was neither waited on nor started.

## Research

**Not required for the config format — the repository determines the approach.**
No web source was consulted and no network access was made. Every field name
this task parses is already present in a checked-in fixture written by a
checked-in generator:

* `fixtures/tiny-llama-2shard/config.json` — `hidden_size`,
  `intermediate_size`, `num_hidden_layers`, `num_attention_heads`,
  `num_key_value_heads`, `vocab_size`, `torch_dtype`.
* `fixtures/generate_fixtures.py:44-64` — the same set as the generator's
  `CONFIG` dict, so the fixture is authoritative rather than incidental.
* `crates/q-source/src/manifest.rs:121` — `config_u64()` already reads such
  fields with `as_u64()`, which is the wrong-type-becomes-`None` behaviour this
  task generalizes.

One numeric fact **was** derived independently, because deriving it from the code
under test would be circular and because `golden.json` does not record it.

**Independent reference — parameter count and byte total.** Read with the
official Python `safetensors` library from the venv at
`…/scratchpad/fxvenv/bin/python` (no network; `safetensors` and `numpy` were
already installed there). Retrieved 2026-08-04. This is the same library
`golden.json` credits (`safetensors==0.8.0`), so it is the established reference
implementation for this repository, not a new one.

```
$ .../fxvenv/bin/python  # script summing get_slice().get_shape() per tensor
tiny-llama-2shard: shards=2 tensors=111 params=302256 bytes=1196736 dtypes={'F32': 109, 'BF16': 2} max_layer=11 layer_count=12
tiny-llama-single: shards=1 tensors=10 params=27744 bytes=104832  dtypes={'F32': 9, 'BF16': 1} max_layer=0  layer_count=1
```

**This changed the implementation and found a plan defect.** `TASK.md` §Data
Contract states `"parameter_count": 299184`. That is `1196736 / 4`, i.e. it
assumes a uniform F32 checkpoint. The fixture holds **two BF16 tensors**
(`crates/q-safetensors/src/ingest.rs::bf16_tensors_are_described_with_the_right_width`),
so the true summed element count is **302 256**:

```
1 196 736 − 2 × 3072 × 2 = 1 184 448 bytes of F32  →  296 112 elements
296 112 + 6 144 BF16 elements                       =  302 256
```

`total_bytes: 1196736` in the same jsonc block is correct, and that asymmetry is
the tell. The **normative** wording — AC-2, "`parameter_count` equals the sum
over `golden.json`'s tensor shapes", and §Scope, "summing tensor element counts
from the manifest — not from config arithmetic" — yields 302 256. Implemented
302 256; `299184` is reported below as a defect in a non-normative illustrative
example. This did not block the task.

Findings that did **not** change the implementation: `golden.json` records
`tensor_count`, `shard_count`, and `total_size_bytes` but **no per-tensor shape
list**, so AC-2's literal "sum over `golden.json`'s tensor shapes" is not
computable from that file. Instruction 7's clean-`git diff -- fixtures/` gate
forecloses adding a field to it. Resolution: the test asserts `tensor_count`,
`shard_count`, and `total_size_bytes` *directly against `golden.json`* and
carries 302 256 as a constant whose derivation is recorded above.

## Summary

* **`q-architecture`** gains `ModelConfigMetadata` — the seven `config.json`
  fields the task's §Scope names, all `Option`, plus `from_config`, `parse`,
  `is_empty`, and `layer_count(observed)`. A field that is missing, of the wrong
  JSON type, negative, or over `u32::MAX` becomes `None`; the remaining fields
  still load. Malformed JSON is refused with the source name as context.
* **`q-catalog`** `upsert_model` / `upsert_resolved` now take
  `&ModelConfigMetadata` in place of a bare `hidden_size: Option<u32>`.
  `hidden_size` is persisted from the config. `layer_count` is
  `observed.or(declared)`: the descriptor-derived count wins whenever the
  manifest shows one, and `num_hidden_layers` fills in only its absence.
  `parameter_count` and `payload_bytes` are now **checked** sums over
  descriptors. New `Catalog::shard_count()` and free
  `observed_layer_count()`.
* **`q-safetensors`** gains `IngestOutcome::shard_count()`. Ingestion of a
  checkpoint with no `config.json`, or with a wrong-typed field, is proved to
  succeed; a corrupt `config.json` is proved to be refused with context.
* **`q-daemon`** `ModelSummary` gains `hidden_size`, `total_bytes` (replacing
  `payload_bytes`), `shard_count`, and `fidelity: "metadata"`.
* **`q-cli`** `inspect` is refactored into a pure, testable `InspectReport` that
  prints every field; absent declared fields render `null`, never `0`.

**No schema migration.** `CURRENT_SCHEMA_VERSION` stays at 1. The three columns
AC-1 – AC-3 need (`hidden_size`, `layer_count`, `parameter_count`) already exist
(`crates/q-catalog/src/schema.rs:43-45`). The other four parsed fields have no
column, no AC, no Test-Cases row, and no place in the §Data Contract, so they
are parsed and surfaced but not persisted — consistent with §Scope, which says
*parse*. A version bump would also have touched three existing migration tests
and collided with the concurrent Wave-2 schema task `QM-0140`.

**No weight byte is read anywhere on this path.** Everything above is a sum over
descriptors already in memory, or a copy out of a `config.json` that
`LocalFsSource::manifest()` already read.

## Architecture conformance

**Governing `ARCHITECTURE.md` sections**

* **§4.1 Import Process** — ingestion produces descriptors from headers and the
  index. `shard_count()` is a fold over those descriptors; nothing new is read.
* **§4.2 Architecture Plugins** — makes `config.json` `q-architecture`'s input.
  `ModelConfigMetadata` is the rest of the file that §4.2 already reads
  `model_type` / `architectures` from, typed. §4.2's rule *"the resolver must be
  allowed to return `unknown`… it must never guess a semantic role just because
  two tensors share the same shape"* is honoured in its numeric form: an
  unusable field is `None`, never a value reconstructed from its neighbours
  (`a_missing_field_is_none_and_is_never_inferred_from_the_others`).
* **§5.1 Model Table** — `hidden_size`, `layer_count`, `parameter_count` are the
  columns being filled. No column was added or altered.
* **§9.2 Data at Each Level** — LOD 0 carries *"parameter count, bytes, global
  distributions"*; the first two now exist and are exact.
* **§14.1 Metadata API** — `GET /v1/models/{id}` is the surface.
* **§18 AC-001 / AC-010** — bounded memory and fidelity labelling; see below.

**Binding ADRs**

* **`ADR-003` (catalog is SQLite, not DuckDB)** — governs over `ARCHITECTURE.md`
  §5. All persistence work stayed in `rusqlite`; `CURRENT_SCHEMA_VERSION` = 1.
* **`ADR-010` (rank ≤ 3 implemented; rank > 3 refuses rather than flattens)** —
  read and found **not applicable at this layer**. ADR-010 places the refusal at
  `bindAxes()` under `GRID-007`, and states that `q_source::TensorDescriptor`

  not mandate here.

## Claim limits

1. **`parameter_count` for `tiny-llama-2shard` is 302 256, not the 299 184
   printed in `TASK.md` §Data Contract.** 299 184 is `total_bytes / 4` and
   assumes a uniform F32 checkpoint; the fixture has two BF16 tensors. The
   normative AC-2 wording ("sum over tensor shapes") gives 302 256, confirmed by
   an independent Python `safetensors` read. **This is a plan defect in a
   non-normative illustrative example and should be corrected in `TASK.md`.** It
   did not block implementation.
2. **AC-2's "sum over `golden.json`'s tensor shapes" is not literally
   computable**: `golden.json` records no per-tensor shape list. The test
   asserts `tensor_count`, `shard_count`, and `total_size_bytes` against
   `golden.json` directly and carries 302 256 as a constant with its derivation
   recorded. A future fixture regeneration could add `parameter_count` to
   `golden.json` and tighten this; instruction 7's clean-diff gate forbade doing
   it here.
3. **`total_bytes` is the summed tensor payload length, not the checkpoint's
   size on disk.** It excludes shard headers and `model.safetensors.index.json`
   (~20 KB for this fixture). The name comes from `TASK.md` §Data Contract; the
   quantity is the existing `models.payload_bytes` column, unchanged.
4. **`fidelity: "metadata"` is a string constant, not a variant of
   `q_source::ResultFidelity`.** That enum has only `Exact | Sampled |
   Approximate` and lives in `crates/q-source`, outside this task's boundary.
   `.plan/DATA_ARCHITECTURE.md` §8 defines `metadata` as a fidelity, so the
   label is correct; it is pinned to `AccessScale::Metadata.reads_payload() ==
   false` by test rather than by the type system. **Adding a `Metadata` variant
   to `ResultFidelity` is a reasonable follow-up for whoever owns `q-source`.**
5. **`u64` overflow of `parameter_count` / `payload_bytes` is guarded by
   `checked_sum` but has no test.** Constructing the case needs descriptors
   whose element counts sum past 2⁶⁴, i.e. shapes that
   `TensorDescriptor::validate()` rejects first. §Error Handling calls the case
   "impossible at 10¹² (≈2⁴⁰), but checked" — it is checked; it is not
   demonstrated.
6. **The `layer_count` fallback fires more rarely than it may appear.** A
   `layers.N.` segment is structural, so even the `generic` plugin observes a
   layer index; the declared `num_hidden_layers` is used only for checkpoints
   whose tensor names carry no such segment. Both branches are tested.
7. **`shard_count` counts distinct `shard_uri` values among *described*
   tensors**, so a resumed ingest reports the shards it actually read, not the
   shards on disk. Deliberate, documented on the method, but it means
   `shard_count` after a partial resume is not the checkpoint's shard total.
8. **`q inspect` keeps the key `described_payload_bytes` while the API uses
   `total_bytes`** for the same quantity. The pre-existing CLI key was preserved
   deliberately; §Data Contract governs only the HTTP route.
9. **No semantic claim is made about any weight.** Nothing here reads a weight
   byte, and no field's meaning is inferred from data — only copied from a
   declaration or summed from descriptors.
10. **`TASK.md` §Repository Evidence is inaccurate on one point** (noted, not
    blocking): it states *"`crates/q-architecture/src/lib.rs` already reads
    `config.json` for `model_type` and `architectures`"*. At `ace7d09` it did
    not — `config.json` is read by `crates/q-source/src/local.rs:177-186` and
    exposed through `ModelManifest::{model_type, declared_architecture}`;
    `q-architecture` only received those two strings as `&str` arguments to
    `Registry::select`. The task's intent still holds, and `ModelConfigMetadata`
    now makes the statement true.

    `/Users/thanh/.qm-worktrees/qm-0012`, which does not exist.** The real
    worktree is `/Users/thanh/Quatricmorph/.qm-worktrees/qm-0012`; branch
