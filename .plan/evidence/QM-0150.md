## Research

**The repository determines nearly everything.** The daemon-client idiom is
`apps/web/model-viewer/src/tile-client.ts` (a 501 is a declared gap carrying a
requirement ID, never retried). The ceiling-and-refuse idiom is
`apps/web/quatricmorph-workspace/src/tensor/block-adapter.ts`
(`assertBlockIsBounded`, and `DaemonBlockSource` throwing rather than returning
plausible zeros). The version-refusal idiom is `CAT-002` as `q-report`
implements it. The required wordings are `.plan/DIAGNOSTIC_ARCHITECTURE.md` §8's
"required wording" column, verbatim.

Three findings needed a decision.

**1. Manifest v1 publishes no per-channel error, and the task's sketch assumes
some.** `TASK.md` §Data Contracts sketches
`Cell = { layerIndex, channelStart, channelEnd, relativeError, aggregated }` and
§Test Cases asks for "12 layers × 512 channels → 6 144 cells". But
`schemas/diagnostics/manifest.v1.json` carries partials only per layer
(`layers[].aggregate`), per expert, and per tensor (`tensors[].aggregate`, full
projection only), plus `ranking[]`, `frontier` and `refusals[]`. It sets
`additionalProperties: false`, so there is no legal place for a per-channel
array either. The engine *computes* per-channel partials
(`.plan/DIAGNOSTIC_ARCHITECTURE.md` line 179, `per_channel: Vec<ChannelPartials>`)
and the manifest does not serialise them.

This is a real gap between the task sketch and the merged schema, and it is
**not** a defect that blocks the work, because the honest resolution is
available and is the one `ARCHITECTURE.md` §19 demands:

* The **column planner** in `src/heatmap.ts` is written against channel bands
  and is exercised at unit (per-channel) resolution, which is where the 6 144-
  and 204 800-cell test rows live. It is the function a future manifest version
  will feed directly, and the one `QM-0153` extends.
* The **manifest adapter** in `src/app.ts` feeds it only what the manifest
  actually publishes: one band per layer from a summary projection (channel
  extent `null` — *not published*), one band per tensor from a full projection,
  each spanning the output channels that tensor's `shape` declares. Every such
  cell is labelled `aggregated`, because it is one.
* No channel value is ever invented. `Cell.channelStart`/`channelEnd`/
  `channelsPerCell` are `number | null`, and `null` means "the manifest
  publishes no extent", which is a different fact from "one channel".

The departure from the sketch is the `| null`, and it is a strengthening.

**2. There is no per-layer detail route.** `.plan/API_CONTRACTS.md` and
`QM-0143` define `GET /v1/diagnostics/{runId}/summary` and
`GET /v1/diagnostics/{runId}` (the full manifest) and nothing between them.
Falling back to the full route for drill-down would download the whole
per-tensor array — precisely what §19 forbids. So `HttpTransport.fetchLayerDetail`
**issues no request at all** and returns a declared gap naming `QM-0152`, which
is the task that adds the route and the binding together. The surface's own
one-request-per-explicit-click behaviour is asserted against an injected
transport with a request log.

**3. No JSON-Schema validator is available offline.** `apps/web/node_modules`
has no `ajv`, and adding one would change the dependency set. So this package
carries a draft-07 **subset** validator driven by the published schema, plus the
guard that makes a subset validator safe: `collectKeywords` enumerates every
keyword the schema actually uses and a test asserts the enumeration is covered
by `IMPLEMENTED_KEYWORDS ∪ ANNOTATION_KEYWORDS`. Add a keyword to the schema
without teaching it here and the suite turns red instead of passing vacuously.

## Architecture conformance

`ARCHITECTURE.md` §19, item by item.

| §19 rule | How this package satisfies it |
| --- | --- |
| **Do not create one cube GLB per weight** | No GLB, no glTF, no 3-D geometry of any kind. `no_source_in_this_package_mentions_a_glb_or_a_tileset` scans every source file for `.glb`, `tileset.json`, `b3dm`, `WebGL` and `WebGPU` and fails on any hit. |
| **Do not store absolute positions for every scalar** | Nothing is positioned per scalar. Cell geometry is computed in `placeCells` from row index, band extent and the plot width — a layout rule, not stored coordinates. The manifest carries no positions and this package stores none. |
| **Do not send the entire tensor into the browser** | Three independent guards. (a) The initial view calls only `ENDPOINTS.summary`; a request-log test asserts the log is exactly `['/v1/diagnostics/run-a/summary']`. (b) A `full` projection arriving on the summary route is refused as `wrong_projection` — the case where the per-tensor array shows up uninvited. (c) `MAX_MANIFEST_PAYLOAD_BYTES` (4 MiB) refuses an oversized body **before parsing it**, and the message names §19. Additionally `HttpTransport.fetchLayerDetail` refuses rather than falling back to the full-manifest route, and asserts that it issued no request. |
| **Do not use Cesium as a tensor compute engine** | Cesium is absent, along with Three.js and every other scene graph — the package's stated boundary. `no_source_in_this_package_imports_cesium_or_three` and `this_packages_dependencies_name_no_3d_renderer` enforce it from two directions (import statements, and the declared dependency maps and scripts). No compute happens in the browser beyond `sqrt(a/b)` over numbers the engine already reduced. |
| **Do not let chat freely execute terabyte-scale expressions** | There is no chat, no query input and no expression evaluation in this package. |
| **Do not assume a colour pattern corresponds to a semantic concept** | See below — this is the one that needed real work. |

### "A colour is not a meaning", concretely

Five mechanisms, each tested:

1. **The legend says what the colour encodes, in the units of the measurement**:
   *"Colour, fill width and glyph all encode relative weight-space error,
   sqrt(sum_sq_delta / sum_sq_base)."* Asserted by
   `the_legend_states_what_the_colour_encodes_in_terms_of_the_measured_quantity`.
2. **The legend says what it is not**, in the image, not in a tooltip:
   *"A colour is not a finding. Cell colour, fill and glyph encode one measured
   quantity — relative weight-space error — and nothing else. What a layer does,
   and what quantising it costs in accuracy, are not measured here."*
   Asserted by `the_legend_states_in_the_surface_that_a_colour_is_not_a_finding`
   and, from the rendered SVG, by `the_legends_not_a_claim_line_is_drawn_in_the_image`.
3. **The scale is declared relative, not absolute**: *"The scale is relative to
   this map: the lightest cell is 0.1 and the darkest is 0.5. It is not an
   absolute threshold."* Without this the darkest cell reads as "bad" in
   absolute terms, which is a semantic claim smuggled in by normalisation.
4. **The required wordings of `.plan/DIAGNOSTIC_ARCHITECTURE.md` §8 are
   reproduced verbatim** — the accuracy caveat, *"Ranked by relative
   weight-space error, a proxy for sensitivity."*, and the frontier's claim
   taken **from the manifest's own `claim` field**, not rewritten
   (`the_frontier_panel_reproduces_the_manifests_own_claim_string_verbatim`).
5. **A mechanical vocabulary check.** `forbiddenClaimTermsIn` matches
   `important`, `unimportant`, `matters`, `dead`/`deadness`, `semantic(s)`,
   `concept`, `understand(s)`, `knows`, `reasoning`, `capabilit(y|ies)`,
   `hessian`, `predicted accuracy` and `accuracy delta` at word boundaries.
   `no_string_the_surface_displays_uses_a_forbidden_claim_term` runs it over
   every string of five different surfaces. It is proved non-vacuous by
   `the_forbidden_claim_checker_is_not_vacuous`, proved not over-eager by
   `the_checker_matches_whole_words_so_ordinary_prose_is_not_flagged`
   (`deadline`, `concepts`), and proved self-consistent by
   `no_required_wording_trips_the_forbidden_claim_checker`.

`AGENTS.md` §4 — **exact / sampled / approximate**. The word from
`manifest.fidelity` appears: in the header (`every value below is EXACT`);
**beside every row of the map** (`layer 1 · exact`); in the legend as its own
entry; on every ranking row, frontier row and expert row; and as
`data-fidelity` on every cell. Aggregation is a *separate* field, never folded
into fidelity — `aggregation_is_labelled_separately_from_fidelity_because_they_mean_different_things`.
`a_sampled_manifest_is_never_labelled_exact_anywhere_in_the_surface` checks
every label at once.

`AGENTS.md` §6 — **never claim semantic understanding** — is rule 5 above.

`.plan/PRODUCT_SCOPE.md` §6 / `SURF-002` — degrade to an aggregate and say so,
never truncate. `no_grid_at_any_dimension_exceeds_the_cell_ceiling` and
`every_channel_index_is_covered_by_exactly_one_cell_at_every_aggregation_factor`
are the pair: bounded, and lossless in coverage.

### The CSS cascade — adequate as it stands, and correctly disclosed
