## Research

**No URL was consulted, and no URL became a build, runtime, or test dependency.**

Every licence recorded in `NOTICE` was read from one of three places, all local:

1. a file checked into this repository (`mm/LICENSE`, file headers in
   `mm/lib/*.js`, `models/distilbert-distilgpt2/README.md`, `Cargo.toml`,
   `package.json`, `python/setup.py`);
2. the `license` field that `cargo metadata --format-version 1` reports for each
   package resolved from `Cargo.lock` — package metadata, not a web lookup;
3. the `license` field that npm records for each package in the checked-in
   `package-lock.json` files.

One licence — SQLite's public-domain dedication — was read from crate source in
the local cargo registry cache (`libsqlite3-sys-0.30.1/sqlite3/sqlite3.c`),
because that C file is compiled into every binary this workspace produces but is
not checked into this repository. That is package source resolved by
`Cargo.lock`, not a URL.

URLs *appear* in `NOTICE` (the `mm` project pages, the Ascender EULA address
embedded in the font's own metadata). They are citations of what a file in this
tree says. Nothing fetches them. `scripts/license-audit.sh` makes no network
request of its own; `cargo metadata` may populate the registry cache, exactly as
`cargo build` already does in the existing `rust` CI job.

Where a licence is commonly *associated* with a project but is not stated in any
file here — the three.js addons, `es-module-shims`, `numpy`, `safetensors`, the
GitHub Actions, the Droid Sans font — `NOTICE` records **not verified** and does
not name a licence. Guessing was the failure mode this task had to avoid.

### Scope items from `## Scope` not covered by a numbered criterion

* *"Confirm no copyleft dependency conflicts with `MIT OR Apache-2.0`"* — 13
  packages name a copyleft licence in their expression, none fatally:
  `r-efi` 6.0.0 is `MIT OR Apache-2.0 OR LGPL-2.1-or-later` (permissive
  alternative available under the `OR`), and twelve `lightningcss*` 1.33.0
  binaries are `MPL-2.0`, all `"dev": true`. Recorded in `NOTICE` §6 and §7 and
  in the JSON as `copyleft_review`.

### A deliberate divergence from the task text

The task's `## Error Handling` says *"A copyleft dependency → fail"*; its
`## Acceptance Criteria` §6 says *"No GPL/AGPL/SSPL dependency is present"*.
These are not the same threshold, and the tree contains MPL-2.0 dev tooling.
`scripts/license-audit.sh` implements the acceptance criterion — GPL/LGPL/AGPL/
SSPL with **no permissive alternative** is fatal — and downgrades weak,
file-level copyleft (MPL-2.0) to a reported, non-fatal review item. The
reasoning is in the script's header comment (lines 27–37) and the outcome is
printed on every run. A reviewer who prefers the stricter reading changes
`is_weak` to `is_copyleft` in the `classify` function; the audit would then fail
on twelve dev-only Vite binaries.

### Fail-threshold ruling

**The implementer was right to implement acceptance criterion 6 over the
`## Error Handling` prose.** Reasoning:

1. **Normative hierarchy.** `## Acceptance Criteria` is the enumerated gate list
   the task's own verification structure keys off; `## Error Handling` is
   descriptive prose. Where they diverge, the enumerated criterion governs.
2. **"Copyleft" is not one threshold.** MPL-2.0 is *file-level* copyleft: it
   attaches obligations to the MPL-licensed files themselves, not to a work that
   merely builds alongside them. Failing the build on MPL-2.0 would encode a
   legal claim the task explicitly disclaims making (`## Out of Scope`: *"legal
   advice"*).
3. **The affected items carry no obligation.** The twelve `lightningcss` 1.33.0
   binaries are `"dev": true` optional platform binaries in Vite's toolchain and
   are redistributed in no build artifact. `r-efi` 6.0.0 offers
   `MIT OR Apache-2.0 OR LGPL-2.1-or-later` — a permissive alternative is
   available under the `OR`, so no copyleft obligation ever attaches.
4. **Nothing is hidden.** All 13 are printed on every run, listed in `NOTICE`
   §6 and §7, and exported as `copyleft_review` in the JSON. The stricter
   reading's *information* is fully preserved; only the exit code differs. A
   maintainer who prefers the strict threshold flips `is_weak` to `is_copyleft`
   in one function — the script header says so.
5. **The divergence is documented**, not silent: in the script header
   (lines 28–37), in the evidence, and in the task's `## Orchestration`.

The stricter prose reading would fail the build on twelve dev-only Vite binaries
while resolving no actual licence risk — a false positive that trains
maintainers to bypass the gate. **Ruling: the implementation is correct.** One
caveat, recorded below.
